# 2DayMovie security review (rebuild/netflix-style)

This review lives under `qa/` (not `docs/`). `docs/` is the GitHub Pages export generated by `scripts/export_site.py`; CI diffs that export against `docs/`, so QA write-ups must not be committed there.

Advisory only. This review does not change application code. Findings are
against the local `rebuild/netflix-style` tree that the QA branch was cut
from. Forge owns any code or header changes.

## Scope

- Flask app (`app.py`), templates, `static/`, public data (`catalog.json`,
  `trailers.json`), CI, Render/Docker/K8s deploy files.
- YouTube embeds must use `https://www.youtube-nocookie.com`, remain
  sandboxed, and must not rehost or download video files.
- Secrets scan (pattern-based; values are not recorded here) and a
  `pip-audit` of `requirements.txt`.

## Content-Security-Policy (recommended)

Set this on every response in Flask `after_request` (and again at the Render
edge if possible). Start here, then tighten after a manual pass of the hero
and the modal player:

```
default-src 'self';
script-src 'self';
style-src 'self';
img-src 'self' https://i.ytimg.com;
connect-src 'self';
font-src 'self';
object-src 'none';
base-uri 'self';
form-action 'self';
frame-ancestors 'none';
frame-src https://www.youtube-nocookie.com;
upgrade-insecure-requests
```

Notes:

- `frame-src` must be **only** `https://www.youtube-nocookie.com`. Do not
  allow `youtube.com` or `youtu.be` as frame sources.
- Do not add `'unsafe-inline'` or `'unsafe-eval'`.
- The current `templates/404.html` uses an inline `<style>` and an inline
  `<script>`. Under the policy above the 404 page will not style or run
  that script. Move both into `static/` (or use a CSP hash/nonce) before
  enabling the policy.
- The app currently loads the YouTube IFrame API from
  `https://www.youtube.com/iframe_api` (`static/js/app.js`). That requires
  `script-src` (and usually `connect-src`) exceptions for `https://www.youtube.com`
  and often further player hosts. Prefer dropping the IFrame API and using
  a plain sandboxed `<iframe src="https://www.youtube-nocookie.com/embed/...">`
  so `script-src` can stay `'self'`. If the API is kept, expect to iterate
  on CSP in a real browser; do not open `script-src` with `'unsafe-inline'`.
- `frame-ancestors 'none'` replaces `X-Frame-Options: DENY`. Sending both is
  fine during the transition.

## Other headers

Already set in `after_request` via `setdefault`:

- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`

Missing (tests are marked `xfail` until these exist):

- `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`
  Set only on HTTPS. In Flask, gate on `request.is_secure` or
  `X-Forwarded-Proto` (Render terminates TLS and forwards the proto). Also
  configure it as a Render custom header so it applies to the static site
  and to HTTP error paths that might not go through Flask.
- `Permissions-Policy` (recommended starting point):

  ```
  accelerometer=(), autoplay=(self "https://www.youtube-nocookie.com"),
  camera=(), display-capture=(),
  encrypted-media=(self "https://www.youtube-nocookie.com"),
  fullscreen=(self "https://www.youtube-nocookie.com"),
  geolocation=(), gyroscope=(), microphone=(), payment=(),
  picture-in-picture=(self "https://www.youtube-nocookie.com"), usb=(),
  interest-cohort=()
  ```

- Clickjacking: `frame-ancestors 'none'` as part of CSP, or
  `X-Frame-Options: DENY` until CSP ships.

### How to set them

Flask (owned by Forge; not applied in this branch):

```python
@app.after_request
def security_headers(resp):
    resp.headers.setdefault("X-Content-Type-Options", "nosniff")
    resp.headers.setdefault("Referrer-Policy", "strict-origin-when-cross-origin")
    resp.headers.setdefault("Content-Security-Policy", CSP)  # the policy above
    resp.headers.setdefault(
        "Permissions-Policy",
        PERMISSIONS_POLICY,
    )
    if request.is_secure or request.headers.get("X-Forwarded-Proto", "").lower() == "https":
        resp.headers.setdefault(
            "Strict-Transport-Security",
            "max-age=31536000; includeSubDomains; preload",
        )
    return resp
```

Render: Dashboard → service → **Headers**, or `headers` on a static site
in `render.yaml`. Prefer setting HSTS and CSP at the edge as well as in
Flask so `/static/*` and platform error pages are covered. Do not duplicate
conflicting policies.

## Iframe sandbox

The modal fallback in `static/js/app.js` builds an `<iframe>` with a
`youtube-nocookie.com` `src` and an `allow` attribute, but **no `sandbox`**.
`YT.Player` (hero and modal) also injects an iframe and never sets
`sandbox`. `hero.js` does query the injected iframe (for `tabIndex`) but
that query runs immediately after `new YT.Player(...)`, so it may run
before the iframe exists.

Required attribute (keeps the official player working):

```
sandbox="allow-scripts allow-same-origin allow-presentation"
```

`allow-scripts` plus `allow-same-origin` lets a framed page remove its own
sandbox; that is an inherent trade-off of the YouTube player and is why
`frame-src` must stay limited to `youtube-nocookie.com`.

## No rehosting

The catalog stores YouTube ids and `i.ytimg.com` thumbnail URLs only.
Playback goes through YouTube's embedded player. Keep it that way:

- Do not download, cache, or serve video bytes (no `.mp4`/`.webm` in the
  repo, no proxy that fetches YouTube media).
- Do not re-encode or rehost audio. Thumbnails may be hotlinked from
  `i.ytimg.com` (current behaviour) or replaced with first-party stills
  you have rights to; do not scrape and rehost copyrighted frame grabs
  as a default.
- `scripts/build_catalog.py` / `build_trailers.py` may call `yt-dlp` for
  metadata. That is fine for duration and id discovery. Do not check
  downloaded media into the tree or serve it.

## Jinja and DOM escaping

- Jinja2 autoescape is on for `.html` templates. The templates do not use
  `|safe` or `Markup`. `{{ base }}` is a path prefix (`""` or `/` or a
  known export prefix) interpolated into URLs; keep it server-controlled.
- Client rendering uses `textContent`, `createElement`, and
  `document.createTextNode`. No `innerHTML` / `insertAdjacentHTML` /
  `document.write` was found under `static/` or `templates/`.
- Search is client-side today (`search.js` → `showResults` sets
  `textContent`). There is **no search HTTP endpoint**. When one is added,
  reflect the query only through autoescaped templates or `jsonify`, and
  return only catalog ids/titles.

## Source-channel leak

A denylist of source channel names, handles, and `youtube.com/@` links is
used in tests (loaded from `CHANNELS_DENYLIST` or a shared path; not
committed under `tests/`). Expected public surfaces (`templates/`,
`static/`, server-rendered HTML) did not contain those values.

High findings still in this tree (counts only; values are not listed):

- `scripts/channels.json` is a 272-entry source list and is already
  tracked in git. It matches the shared denylist byte-for-byte.
- `scripts/channel_resolution.json` is a 272-entry list with `name`,
  `group`, `status`, and `url`.
- `data/catalog_sources.json` is not served by Flask (`/data/` only
  allows `catalog.json` and `trailers.json`) but is in the repo and
  names `channels_with_videos` (150), `channels_without_videos` (122),
  and `skipped` (466).
- One public catalog title (wildlife, title length 67) contains a
  denylist name (length 16). That title will be visible in the UI once
  `/data/catalog.json` is loaded. The dedicated test
  `test_denylist_not_in_public_catalog_or_trailers` fails for this.

Recommendations for Forge (the repository owner's explicit OK is required before any history rewrite):

- Stop tracking the source lists; gitignore them; keep them off the
  public GitHub repo. A history scrub is a separate, explicit decision.
- Rewrite the one catalog title so it does not include a source name.
- Keep serving only `catalog.json` and `trailers.json` from `/data/`.

## Secrets scan

A gitleaks-style ripgrep pass was run over the tree (AWS key prefixes,
private key sentinels, GitHub/Slack/Stripe token prefixes, generic
`api_key` / `password` / `token` assignments). **No live secret values
were found.** Observations (no values printed):

- `render.yaml` and deploy docs still mention `TMDB_API_KEY` /
  `DATABASE_URL`. The rebuilt Flask app does not read them. They are
  `sync: false` (Render) or empty/optional (K8s). Remove unused secret
  slots so they are not reintroduced by habit, or keep them only if a
  future feature needs them.
- `docker-compose.yml` sets a default Grafana username and password of
  `admin` / `admin` for local monitoring. That must never be used on a
  reachable host; prefer an env file that is not committed.
- `.env.example` has no credentials. `.gitignore` already excludes
  `.env`, `*.pem`, `*.key`, `credentials.json`, `secrets.json`.

## Dependency audit

`pip-audit` was run on 20 Nov 2026 (Europe/Warsaw) against a clean venv
installed from `requirements.txt`. Three packages reported known
vulnerabilities (IDs only; upgrade is owned by Forge):

- Flask 3.1.2 — PYSEC-2026-2151 / CVE-2026-27205, fixed in 3.1.3.
  `Vary: Cookie` is not always set when the session object is accessed.
  This app does not use login sessions today; still upgrade.
- python-dotenv 1.0.1 — PYSEC-2026-2270 / CVE-2026-28684, fixed in 1.2.2.
  Symlink follow when rewriting `.env` (local attacker). Low relevance
  here if `.env` is not rewritten in production.
- pytest 8.3.5 — PYSEC-2026-1845 / CVE-2025-71176, fixed in 9.0.3.
  Predictable `/tmp/pytest-of-{user}` directories on UNIX. Dev/CI only.

gunicorn 23.0.0 and prometheus-client 0.21.1 had no findings. Current
pins: Flask 3.1.2, python-dotenv 1.0.1, pytest 8.3.5, gunicorn 23.0.0,
prometheus-client 0.21.1. Re-run `pip-audit` when dependencies change.

## Other notes

- `/metrics` is public. That is useful for the Docker health path but
  exposes request counters. If the Render service is on the public
  internet, consider restricting `/metrics` (network policy or basic
  auth) before enabling a scraper.
- Existing `.github/workflows/ci.yml` and `pages.yml` use unpinned
  `actions/checkout@v4` and `actions/setup-python@v5` tags. The new
  `qa.yml` pins full SHAs. Prefer pinning the existing workflows too.
- `FLASK_DEBUG` is off by default; keep it off in production (`render.yaml`
  already sets `0`).
- Hero autoplay of muted trailer clips has no visible Pause control
  (WCAG 2.2.2). That is an accessibility finding, recorded in
  `qa/QA-CHECKLIST.md`.
